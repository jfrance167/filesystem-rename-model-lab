## Primary semantics and uncertainty

[Linux rename(2)](https://man7.org/linux/man-pages/man2/rename.2.html), man-pages6.19, read October5: ordinary rename preserves other hard links and existing open descriptors. Same-file aliases are a successful no-op; replacement changes the destination name. Atomic destination replacement concerns namespace visibility, not batch isolation, durability or permissions. Exchange swaps two existing entries; noreplace changes occupied-destination behavior; whiteout adds another object/capability. EXDEV concerns mounted filesystem boundaries. The NFS caveat says a reported failure can follow an actual rename, so do not infer universal unchanged state from failure.

[fsync(2)](https://man7.org/linux/man-pages/man2/fsync.2.html), read directory-sync passage: file synchronization alone need not persist its containing directory entry. This supports the separate durability limitation, not a persistence algorithm.
